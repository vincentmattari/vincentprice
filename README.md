# 재고 적정 판매가 산출

선입선출(FIFO)이 관리되지 않아 발주가·입고가를 그대로 신뢰할 수 없는 재고 데이터에서,
**가격 미기재(0원) 레코드를 보정**해 부품 2,180개의 유효원가와 판매가를 산출합니다.

👉 **[산출 결과 페이지 열기](https://vincentmattari.github.io/vincentprice/)**

---

## 무엇이 문제였나

원본은 부품별 **집계값**만 담고 있습니다 — 부품명·메이커, 발주/입고 횟수, 발주평균가, 입고평균가,
전체평균가·최소가·최대가. 개별 거래 내역이 없어 선입선출 원가를 역산할 수 없습니다.
데이터를 검증하면서 두 가지 구조적 결함을 확인했습니다.

### (가) 발주평균가·입고평균가는 '단가'가 아니다

2,180행 **전부**에서 `발주평균가 + 입고평균가 = 전체평균가`가 성립합니다.
두 값은 각자의 건수가 아니라 **전체 건수(CNT)로 나눈 기여분**입니다. 실제 단가를 보려면 되돌려야 합니다.

```
발주단가 = 발주평균가 × CNT ÷ 발주건수
입고단가 = 입고평균가 × CNT ÷ 입고건수
```

### (나) 0원은 '무료'가 아니라 '미기재'다 — 핵심

CNT=2이고 최소가=0, 최대가>0인 **365개 부품 전부**가 `전체평균가 = 전체최대가 ÷ 2`를 정확히 만족합니다.
한 건은 가격이 있고 다른 한 건은 0원이라 평균이 **정확히 절반으로 희석**된 것입니다.

```
51747255413 → 발주 1건 @ 127,200원 · 입고 1건 @ 0원
전체평균가 63,600원 = 127,200 ÷ 2   ← 실제 원가의 절반
```

CNT=1인 부품 959개 중 410개(**42.8%**)가 가격 0원입니다.
즉 약 45%의 레코드에 가격이 없고, 이 0원들이 평균에 섞여 **전체평균가를 구조적으로 끌어내립니다.**
전체평균가를 그대로 원가로 쓰면 손해를 봅니다.

## 산출 공식

0 오염은 **아래쪽으로만** 작용하므로 하한과 상한을 세우고 그 사이를 추정합니다.

```
원가하한 L = max(전체평균가, 발주단가, 입고단가)   ← 0 오염을 감안한 최선의 하한
원가상한 U = 전체최대가                          ← 실제로 기재된 가장 높은 가격

미기재추정 z = min( CNT × (1 − 전체평균가/U),    ← 데이터가 허용하는 최대치
                   CNT × 0.45 )                ← 전사 미기재율 사전값

유효원가 C = 전체평균가 × CNT ÷ (CNT − z),  단 [L, U] 범위로 제한
판매가    = C × (1 + 마진율)
```

두 항 중 작은 쪽을 쓰는 이유: 평균과 최대가의 차이가 *전부* 미기재 탓은 아닙니다.
거래가 많은 부품은 실제 로트별 원가 변동도 섞여 있어, 45% 사전값으로 상한을 걸어 과대 보정을 막습니다.

**검증** — 진값을 아는 유형(발주 1건 유가 + 입고 1건 0원)에서 산출값이 정확히 최대가와 일치합니다.
`51747255413`의 유효원가는 **127,200원**으로 복원됩니다.

## 결과

| 항목 | 값 |
|---|---|
| 전체 부품 | 2,180개 |
| 판매가 산출 가능 | 1,612개 (73.9%) |
| 산출 불가 (F등급) | 568개 (26.1%) |
| 원가 상향 보정 | 1억 4,973만 → **1억 8,424만원 (+23.0%)** |
| 메이커 | 25개 |
| 부품명 미기재 | 102건 |

부품명·메이커는 산출에는 쓰이지 않고 **결과 확인용**입니다. 페이지에서 부품명 검색과 메이커 필터로 쓰이며,
CSV·엑셀 산출물에도 함께 실립니다.

### 신뢰 등급

등급은 `원가하한 ÷ 원가상한`, 즉 **추정 구간이 얼마나 좁은지**로 매깁니다.

| 등급 | 기준 | 부품 수 | 의미 |
|---|---|---|---|
| **A** | ≥ 0.95 | 1,338 | 가격 일관 — 확정 수준 (CNT=1이면 단일 관측) |
| **B** | ≥ 0.60 | 140 | 편차 경미 — 그대로 사용 가능 |
| **C** | ≥ 0.30 | 99 | 편차 큼 — 검토 권장 |
| **D** | < 0.30 | 35 | 편차 심각 — 수동 확인 필수 |
| **F** | 최대가 = 0 | 568 | 모든 거래가 0원 — **산출 불가** |

> **C·D·F 등급은 일괄 적용 대상이 아닙니다.** C·D는 구간이 넓어 보수가를 쓰거나 실제 매입가 확인이 필요하고,
> F는 외부 가격표(제조사 MSRP, 공급처 견적)를 붙이는 것 외에 방법이 없습니다.

## 한계

- 원본에 **거래 일자와 수량이 없습니다.** 진짜 FIFO 원가나 최근 매입가 가중은 불가능하며, 이 산출은 "시점 무관 대표원가"입니다.
- 미기재율 45%는 **전사 단일값**입니다. 부품별 실제 미기재율이 다르면 개별 오차가 생깁니다.
- 전체최대가에 **이상치**(오타, 수량 묶음 입력)가 섞였다면 상한이 부풀려집니다. D등급이 특히 의심 대상입니다.
- 마진율은 원가회수 기준일 뿐 **시장 경쟁가·회전율·부품 희소성은 반영되어 있지 않습니다.**
- 근본 해결책은 **입고 시 단가 필수 입력**과 로트 단위 관리입니다. 이 산출은 그때까지의 보정책입니다.
- 품번 `6R0955681`이 **메이커만 다른 중복 행**으로 두 번 들어 있습니다(PRS / VW). 양쪽 모두 거래가 전부 0원인
  F등급이라 판매가에는 영향이 없으나, 품번을 기준키로 쓰실 경우 중복 처리가 필요합니다.

## 실행 방법

> **원자료 미포함** — 발주·입고 원본 데이터(`*_발주_입고_횟수_*.xlsx`)는 저장소에 포함하지
> 않았습니다. 아래 스크립트를 직접 실행하려면 해당 파일을 저장소 최상단에 두어야 합니다.
> 스크립트가 패턴으로 자동 인식합니다.
> 산출 **결과**는 `index.html`·`data.json`·`적정판매가_산출결과.xlsx`에 모두 담겨 있어,
> 결과만 확인하실 경우 원자료는 필요하지 않습니다.

```bash
pip install openpyxl

python verify_assumptions.py   # 산출 전제가 성립하는지 검증 (모두 OK여야 함)
python build_price.py          # index.html · data.json · 적정판매가_산출결과.xlsx 생성
```

| 파일 | 설명 |
|---|---|
| `verify_assumptions.py` | 두 전제를 원본 데이터로 검증 |
| `build_price.py` | 산출 엔진 — 원가 추정, 등급 판정, 산출물 생성 |
| `render_md.py` | 방법론 문서 마크다운 → HTML 렌더러 |
| `template.html` | 결과 페이지 템플릿 (데이터 주입 전) |
| `template_method.html` | 방법론 페이지 템플릿 (본문 주입 전) |
| **`산출방법론.md`** | **방법론 문서 — 내용의 원본.** 고치려면 이 파일을 수정 |
| `산출방법론.html` | 방법론 페이지 (`.md`에서 생성) |
| `index.html` | **산출 결과 페이지** — 데이터 내장 단일 파일, 마진율 조정 가능 |
| `적정판매가_산출결과.xlsx` | 전체 부품 산출 결과 (엑셀) |
| `data.json` | 산출 결과 원본 데이터 |

방법론은 `index.html`에서 분리해 **별도 문서**로 두었습니다.
`산출방법론.md`가 내용의 원본이고 `산출방법론.html`은 `build_price.py` 실행 시 생성되므로,
**`.html`을 직접 고치지 마세요** — 다음 빌드에서 덮어씁니다.

페이지에서 마진율 슬라이더를 움직이면 표가 즉시 갱신되고, 현재 필터·마진 기준으로 CSV를 내려받을 수 있습니다.
품번·부품명 검색, 메이커 필터, 신뢰 등급 필터, 열 정렬을 지원합니다.

두 스크립트 모두 **컬럼을 헤더 이름으로 찾습니다.** 컬럼이 추가되거나 순서가 바뀌어도 그대로 동작하며,
`부품명`·`메이커`는 있으면 싣고 없으면 건너뜁니다. 필수 컬럼이 없으면 어떤 헤더를 찾았는지 알려주고 중단합니다.
